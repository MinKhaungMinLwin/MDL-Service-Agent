# MDL Project Handoff

## Project Goal

The goal of this MDL project is to create an integrated Standard MDL based on classified MDLs from 7 previous projects. Later, when a new ITB is provided, the system should identify relevant items/packages from the ITB and automatically generate or match the required document list.

The current target flow is:

```text
1. Generate integrated Standard MDL from 7 classified MDLs
2. Extract or identify ITB keywords/packages and match related Standard MDL sections
3. Add complementary documents that are not explicitly mentioned in ITB but are required by package/system/equipment logic
```

Currently, the work is focused on step 1: Standard MDL generation.

## Current Rules

### 1. Vendor / EPC Scope Separation

Currently fixed groups:

```text
ACC Vendor Document List
HRSG Vendor Document List
DCS Vendor Document List
EPC Document List
```

For the latest test, only these three sections were generated:

```text
ACC Vendor Document List
HRSG Vendor Document List
DCS Vendor Document List
```

### 2. Forced L1

`System (L1)` must be selected only from section 3 of:

```text
lv1lv2강제프롬프트.docx
```

### 3. Forced L2

`Sub-System / Area (L2)` must be selected only from:

```text
1. Equipment
2. Building
```

If no match exists, it is set to `General`.

### 4. L3 Is Not Forced

At first, L3 was also forced to the same Section 1/2 taxonomy. That caused L2 and L3 to become almost identical, destroying the hierarchy.

Current rule:

```text
L1 = forced taxonomy
L2 = forced taxonomy
L3 = generated by LLM as a concrete equipment/object based on L1/L2 and source titles
```

Examples:

```text
L2: Air Cooled Condenser
L3: ACC Fan Motor

L2: Bypass stack
L3: Diverter Damper

L2: DCS
L3: Burner Management System
```

### 5. Title Rules

Current title rules:

```text
- Do not force Standardized Document Title into a simple [L3] + [Document Type] pattern
- Remove project-specific qualifiers such as Block / Unit / Project / For Block 2
- Preserve the original title in Source Titles
- Merge rows that differ only by block/unit/project qualifier
- Split Data Sheet & Drawings into separate Data Sheet and Drawing rows
- Use abbreviations in titles: HRSG, ACC, DCS, GTG, STG, BOP, MOV, P&ID, I&C, etc.
```

## Previous Attempts

### 1. Rule-Based Integration

`build_standard_mdl.py` is fast and stable, but many titles become too simple, mostly `Equipment + Document Type`. It does not feel as engineering-restructured as the Doosan Copilot result.

### 2. LLM-First Integration

R&N + Fadhili were tested by having the LLM directly read raw MDL rows and generate an integrated result.

Issues:

```text
- About 2 hours for only 2 projects
- Too slow for all 7 projects
- Risk of result variance
```

The current practical approach is:

```text
rule-based candidate reduction + package-grouped LLM regeneration
```

### 3. L3 Forced Mistake

When L3 was forced using the same Section 1/2 taxonomy, hierarchy was removed:

```text
L2 = HRSG
L3 = HRSG
```

Now L3 is generated by the LLM.

## Difference from Doosan Copilot Result

Doosan Copilot prompt strongly required:

```text
- Complete Vendor / EPC separation
- System → Sub-System → Equipment → Document Type hierarchy
- Do not simply list existing documents
- Reconstruct based on engineering logic
- Actively supplement missing documents
- Strong Foundation document generation
```

Currently reflected in our prompt:

```text
- Vendor/EPC separation
- Merge/standardize
- L1/L2 forced taxonomy
- L3 concrete equipment generation
- Block qualifier removal
- Data Sheet & Drawings split
- Abbreviation usage
```

Still weak or not implemented:

```text
- Mandatory Foundation generation
- Building internal breakdown
- Infrastructure mandatory inclusion
- Expert-Inferred missing document generation
```

## Current Limitation

The latest result is entirely:

```text
Evidence Type = Source-Grounded
Review Status = Approved Source-Grounded
```

This means the LLM did not generate new missing documents.

Reason:

```text
- Current prompt is still mainly source-evidence based
- No package-level expected deliverable checklist exists yet
- Expert-Inferred second pass has not been implemented
```

To generate missing documents:

```text
1. First pass: Source-Grounded merge/standardization
2. Second pass: gap analysis using package-level expected deliverable checklist
3. Add missing rows as Expert-Inferred + Needs Doosan Review
```

## Current Conclusion

The current best structure is:

```text
Filter package candidates from classified MDL
→ force L1/L2 using docx taxonomy
→ let LLM generate L3 as concrete equipment/object
→ LLM merges, deduplicates, and regenerates titles per package
→ post-process block/unit removal, composite deliverable split, validation
→ Doosan review and confirmation
```
